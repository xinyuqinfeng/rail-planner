# 离线铁路高性价比中转路径规划工具

个人本地离线使用的铁路中转路线规划与比价工具。**只做路线查询与比价参考**：无登录、无抢票、无下单、无实时接口调用，**路线计算阶段全程零网络请求**。



**项目起因**是我经常刷到网上旅行博主推荐的线路，12306本身官网自带的中转功能不太会查到的线路，但其实仔细比对发现有的线路时间比直达增加不了多少，但是价格却便宜许多，所以让vibe了这个应用，希望有帮助



- 支持 **1/2/3 次中转**（≥4 次直接截断），自动挖掘官方平台不优先推送的高性价比换乘方案
- 覆盖 **高铁 / 城际 / 动车 / 普速** 全线，席别支持 **硬座、硬卧（上/中/下）、软卧（上/下）、软座、无座、二等座、一等座、商务座**
- 提供 **图形界面**（双击即用）与 **命令行** 两种使用方式

> **免责声明**：本工具仅为路线规划参考，票价为国铁基准公布价；动车组存在市场化浮动折扣，临客/调图可能变动，真实票价、余票请前往 12306 官方核验。

## 三、数据来源与管线

**唯一数据源**：车次详情页（`gaotie.com.cn/checi/<车次>.html`），单页同时给出
每个停靠站的**到发时刻、累计里程、累计运行时长、以及全部席别的累计票价**
（硬座/硬卧上中下/软卧上下/软座/无座/二等座/一等座/商务座）。

原 12306 时刻表数据集仅用于得到车次号清单（用于构造抓取 URL），**不再作为时刻表来源**——
因为两个数据集的调图期不同，车次号相同但运行区间已变，按车次号匹配票价只有约 16% 命中率。

管线三步（`tools/fetch_fares.py`）：

1. **抓取**：10,000+ 个车次页，5 并发 + 请求间隔 80–220ms，支持断点续抓
2. **里程交叉校验**：同一站对会出现在多趟车次中，取里程差的中位数作为标准区间里程，
   修正个别页面的错误里程（实测修正 1,148 处，例如某车次把汉中→广元记成 38km）
3. **票价线性化**：页面给的是累计价，而国铁长途存在递远递减，跨线车次的尾段累计差会被
   严重压缩（曾出现「商务座 ¥27 比二等座 ¥39.5 还便宜」）。改为按全程平均单价线性化，
   区间票价 = 里程差 × 单价，既保持席别间的正确比例，又保证总价守恒

另有 `data/csv/station_code.csv`（12306 官方静态码表，单次请求，3,389 站）用于填充电报码。

### 票价精度

票价按可信度分三级回退（查询时自动选择最优来源）：

| 优先级 | 数据源 | 说明 |
|---|---|---|
| ① **12306 官方票价** | `od_fare_12306.csv` | 由 `tools/fetch_12306_fare.py` 直连 12306 官方接口抓取，**完全准确**。同 OD 同席别多车次时取最低价 |
| ② 车次详情页 OD 表 | `od_fare.csv` | 每趟车「始发站 → 各站」的实际可售票价，12 万条 |
| ③ 累计价差值 | 库内 `stop_schedule` | 同一趟车累计票价之差，兜底用，跨线长交路会略偏低 |

**12306 接口要点**（`tools/fetch_12306_fare.py` 已封装，可直接用）：

```bash
# 全国全量抓取（19.7 万个站对，约 66 小时，支持断点续抓、可分多次跑，热门优先）
python tools/fetch_12306_fare.py --all --min-gap 1.2
# 按车次覆盖数自动挑选热门 OD 抓取前 5000 个（约 1.7 小时）
python tools/fetch_12306_fare.py --limit 5000
# 抓取指定线路的真实票价（每行 出发站,到达站）
python tools/fetch_12306_fare.py --ods my_ods.txt
```

- **进度实时显示**：百分比 / 已完成数 / 成功失败数 / 速度 / 已用时间 / 预计剩余时间
- **断点续抓**：已抓 OD 记录在 `fare12306_done.txt`，中断后重跑自动跳过
- **抓取时间记录**：写入数据库 `meta` 表，界面底部显示"抓取于 X 天前"，**超过 15 天会提示更新**
- Cookie：GET `/otn/leftTicket/init` 取 `Set-Cookie` 即可，**不需要 RAIL_DEVICEID**
- 端点动态化：`/otn/leftTicket/query` 会返回 `{"c_url":"leftTicket/queryG"}`，取它作为真正的查询端点
- **票价无需额外接口**：查询结果第 39 字段 `yp_info`，每 10 字符一段（首字符=席别码，第 2–6 位÷10 = 元）
- 电报码必须准确（汉中=HOY、广元=GYW、西安=XAY、西安北=EAY），取自 `data/csv/station_code.csv`
- 实测：50 个 OD → 17,797 行票价、零失败、约 1 秒/OD；抓完后执行 `raildata` 导入 + `build_gui` 重建即可

## 四、算法设计

### 4.1 搜索：A* 启发式

- 状态：`(当前车站, 到达时间, 累计票价, 已中转次数, 路径记录)`
- 启发函数：`h(n) = 从当前站直达终点的最低票价`（剩余费用下界），优先队列按 `f = 累计票价 + h(n)` 出队
- 时间用「自车次始发站的累计运行分钟」计算，跨天自动正确处理
- 最大深度：中转次数 ≤ 3（最多 4 段行程）
- 席别：`auto` 时每段取可用席别最低价；指定席别时该段必须售此席别，否则跳过该分支

### 4.2 四层剪枝（搜索过程中丢弃，不生成完整路径后再过滤）

| 剪枝 | 规则 |
|---|---|
| ① 深度剪枝 | 中转次数 ≥ `MAX_TRANSFER_COUNT`(3) 终止该分支 |
| ② 时间硬剪枝 | 存在直达方案时，**中转方案**的 `累计耗时 + 剩余时间下界 > 直达最短耗时 × MAX_TIME_MULTIPLE(2.0)` 则剪枝。**直达方案本身是基准，全部保留**——否则会出现「基准显示 ¥48（最便宜的慢车）、结果里最便宜却是 ¥149」的矛盾 |
| ③ 支配剪枝 | 同一 `(车站, 中转次数)` 下，已有「**到达更早 + 票价更低 + 出发不更早**」的状态则丢弃（三维 Pareto） |
| ④ 价格剪枝 | 存在直达且已在途中，累计票价 ≥ 直达最低票价（票价单调递增）则剪枝 |

> 支配剪枝的第三维（首段发车时间）不可省：否则「凌晨出发、到得早但耗时极长」的状态会把「早上出发、耗时合理」的可行换乘误判为更差而剪掉。

基础过滤：换乘间隔 < `MIN_TRANSFER_GAP`(25 分钟) 直接剔除。

### 4.3 打分排序

**直达基准的选取规则**：优先采用 **高铁 / 城际 / 动车** 的直达（取其最低价与最短耗时）；
只有该 OD **完全没有快速直达**时，才回退到普速直达。
这样才能避免基准被普速慢车拉低 —— 例如汉中→成都，普速 ¥48（8.5 小时）会把动车 ¥149（2.3 小时）
的基准掩盖掉，导致所有方案都显示「比直达贵」。

```
有直达：
  save_ratio = (直达最低票价 - 总票价) / 直达最低票价
  extra_hour = (总耗时 - 直达最短耗时) / 3600
  score      = save_ratio * 100 - extra_hour * 15
  save_ratio ≥ 10% → 标记「高性价比低价中转」

无直达：
  score = -总票价 * 0.01 - (总耗时/3600) * 5
```

结果按得分降序，最多输出 `MAX_RESULT_COUNT`(200) 条；另有**多样性控制**（同一「换乘站序列 + 末段车次」最多保留 3 条），避免同类方案占满名额。

## 六、存储与性能

- 单文件 SQLite + WAL；`stop_schedule(station_name, depart_time)` 联合索引实现「某站某时刻后出发车次」毫秒级命中，无全表扫描
- `station(city_name)` 索引支撑城市 → 多车站展开：先按站名方位后缀（东/南/西/北）与机场特例推断，再用「站名以已知城市名开头」做二次归并（如「北京朝阳」→ 北京、「上海松江」→ 上海）
- 实测城市展开：北京 10 站、广州 9 站、上海 5 站、成都/重庆/西安/杭州/天津 各 4 站
- 查询阶段按站点懒加载 + 内存缓存出发段
- 导入后自动重建索引 + `ANALYZE` + `VACUUM` + WAL checkpoint
- 实测（10,175 车次 / 96,245 条停靠站记录 / 2,599 座车站）：单次查询约 **3 秒**（指定卧铺席别约 5 秒），数据库约 **14 MB**，单文件 GUI 约 **25 MB**


| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | 生成「汉中→广元→重庆」1 次中转方案且排名靠前 | 输出中检查该组合及其排名 |
| 2 | 自动过滤换乘间隔 < 25 分钟的方案 | 所有方案换乘等待 ≥ 25 分钟 |

## 八、已知限制

- 时刻表为抓取时刻的图定车次快照，不含临客、不含每日开行规律（如周末线）；调图后重新跑一次 `fetch_fares.py` 即可更新
- 席别票价为抓取时刻的**公布全票价**，不含市场化浮动折扣与临客加价；卧铺按上/中/下分别计价
- 抓取源页面的里程偶有错漏，已用「全路网区间里程中位数」交叉校验修正（实测修正 1,148 处），仍可能有残留
- 不查询实时余票，不支持选座偏好
